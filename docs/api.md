# SadakWatch API

Base URL: wherever `cmd/api` listens (default `http://localhost:8080`). All bodies are JSON unless noted. Read endpoints are public; writes take a key in `Authorization: Bearer <key>` or `X-API-Key: <key>` when the server configures one.

## Ingestion

### `POST /v1/events` — ingest key

Accepts one event object, a JSON array, or `{"events": [...]}` (max 500).

```json
{
  "event_id": "1b6f6c3e-9a51-4b36-9d0e-2c0b7c1f4a10",
  "vehicle_id": "bus-17",
  "event_type": "pothole",
  "severity": "high",
  "confidence": 0.82,
  "latitude": 28.6139,
  "longitude": 77.2090,
  "accuracy_m": 4.0,
  "detected_at": "2026-10-23T06:30:15Z",
  "speed_kph": 32,
  "heading_degrees": 90,
  "source": "vision",
  "image_uri": "/media/2026/10/23/….jpg"
}
```

* `event_id` — UUID generated by the producer; re-sending it is reported as a duplicate, so retries are safe. Omit it to let the server assign one.
* `event_type` — `pothole`, `road_crack`, `broken_surface`, `waterlogging`, `debris`, `road_edge_damage`, `missing_lane_marking`, `damaged_manhole`, `speed_breaker`.
* `severity` — `unknown` (default), `low`, `medium`, `high`, `critical`.
* `source` — `vision` (default), `accelerometer`, `manual`.
* `detected_at` must be within the last 90 days and not more than 10 minutes in the future.

Response (`201` for a single new event, otherwise `200`):

```json
{"accepted": 1, "duplicates": 0, "rejected": 0,
 "results": [{"event_id": "…", "defect_id": "…", "duplicate": false, "new_defect": true}]}
```

In a batch, invalid events get an `error` in their result and the rest are stored. A single invalid event returns `422` with `problems`. Infrastructure failures return `5xx` and nothing should be acknowledged by the client.

### `POST /v1/media` — ingest key

`multipart/form-data` with a `file` field (JPEG, PNG, WebP or MP4, ≤ 15 MB; content is sniffed). Returns `201 {"uri": "/media/YYYY/MM/DD/<uuid>.jpg"}`. Put that URI in the event's `image_uri`. Files are served from `GET /media/…`.

## Defects

A defect is the persistent physical issue; events are its observations.

### `GET /v1/defects`

Query parameters (all optional):

| Param | Example | |
|---|---|---|
| `bbox` | `76.7,30.7,76.8,30.8` | minLon,minLat,maxLon,maxLat |
| `type` | `pothole,waterlogging` | comma-separated |
| `status` | `active` or `open,acknowledged` | `active` = open + acknowledged + in_progress |
| `since` | `2026-10-01T00:00:00Z` | last seen at or after |
| `limit` | `1000` | default 500, max 5000 |
| `format` | `geojson` | returns a GeoJSON FeatureCollection |

Each defect carries `observation_count`, `vehicle_count`, worst `severity`, `max_confidence`, `first_seen`, `last_seen`, `status`, `latest_image_uri`, `recurrence_of` (set when it reappeared after being closed) and `responsibility` (road, authority, division, contract, contractor, officer, source reference).

### `GET /v1/defects/{id}`

The defect plus `observations` (newest first, up to 200) and remediation `history`.

### `PATCH /v1/defects/{id}` — admin key

```json
{"status": "in_progress", "note": "Work order WO-2291 issued", "actor": "AE North"}
```

Statuses: `open`, `acknowledged`, `in_progress`, `resolved`, `rejected`. Setting the current status again returns `409`. A detection near a resolved/rejected defect within 180 days opens a new defect linked by `recurrence_of`.

## Events

* `GET /v1/events` — same filters as defects (`bbox`, `type`, `since`, `limit`) plus `vehicle_id` and `defect_id`.
* `GET /v1/events/{id}`

## Responsibility

* `GET /v1/responsibility?lat=30.73&lon=76.78&at=2026-03-01` — who is answerable for that point on that date.
* `POST /v1/admin/roads` — admin key. GeoJSON FeatureCollection of `LineString`/`MultiLineString` features. Properties: `external_id` (upsert key), `name`, `authority`, `authority_type`, `division`, `contractor`, `contract_reference`, `contract_scope`, `valid_from`, `valid_to` (YYYY-MM-DD), `officer`, `officer_designation`, `source_reference`. Returns counts and per-feature errors. See `db/seed/demo-roads.geojson`.

## Operations

* `GET /healthz` — process is up.
* `GET /readyz` — database reachable.
* `GET /v1/stats` — totals, counts by type/status, contractors and authorities with the most open defects, average hours to resolution.
* `GET /v1/meta` — taxonomy, statuses and whether keys are required.

|---|---|---|

| `MIN_SPEED_KPH` | `5` | ignore frames while parked |
| `QUEUE_MAX_ITEMS` | `20000` | oldest are evicted beyond this |
| `SIMULATE` | – | `1` drives a simulated loop (`SIM_LAT`, `SIM_LON`, `SIM_RADIUS_M`, `SIM_SPEED_KPH`, `SIM_EVERY_SECONDS`) |
